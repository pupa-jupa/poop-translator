# Проверки версии 1.8.0

Сверено 2026-09-23.

| Команда | Что проверяет | Чего не доказывает |
| --- | --- | --- |
| `npm test` | Каталог 39 языков, миграция v1–v3 в v4, импорты, словарь, автоопределение и активация модели, PDF-бюджеты и пакеты, OCR, UI, перетаскивание, storage и DOM-сессия | Работа настоящей языковой модели и качество OCR на произвольных картинках |
| `npm run typecheck` | TypeScript в src, tests и Vite config | Выполнение кода браузером |
| `npm run build` | Генерация иконок, popup/PDF/background/offscreen, IIFE content script, локальные OCR-ресурсы и PDF.js worker | Проверка типов и реальный перевод |
| `npm run smoke` | Совпадение версии в package, исходном и собранном manifest; обязательные файлы, PDF.js worker/license, MV3, OCR-permissions/CSP, отсутствие ESM import в content bundle, локальные OCR-модели, лицензии и два примера словаря | Полная валидация всех словарей и браузерные сценарии |
| `npm run smoke:browser` | Chromium, UI, runtime RPC, PDF на 2 и 51 странице, предупреждение и единый TXT, OCR PDF-скана, двухэтапную активацию пары через заглушку, перетаскивание карточки и управление стрелками, варианты словаря, импорт, фокус и storage | Настоящий Chrome Translator, качество OCR на сложных изображениях и native ПКМ |
| `npm run smoke:ocr` | Реальный снимок вкладки, CSS→bitmap crop, offscreen/Tesseract, переключение моделей и распознавание EN/RU/DE/JA/KO/упрощённого и традиционного ZH, а также белых подписей на цветном фоне | Перевод распознанного текста и качество OCR на произвольных шрифтах |
| `npm run smoke:real` | Настоящий Translator API в Playwright Chromium, обе пары и выделение при доступном пакете | Native ПКМ; гарантированную загрузку компонента в каждой среде |

CI выполняет `npm test`, `npm run typecheck`, `npm run build` и `npm run smoke` после `npm ci`. Браузерные сценарии запускаются отдельно: установите Chromium через `npx playwright install chromium`. Они открывают видимое окно, используют временный профиль и удаляют его после завершения. На Linux нужен display, например `xvfb-run -a npm run smoke:browser` после установки Xvfb и зависимостей браузера.

Для сохранения скриншота на Windows:

```powershell
$env:POOP_TRANSLATOR_SCREENSHOT_PATH = 'output/playwright/poop-translator-popup.png'
npm run smoke:browser
Remove-Item Env:POOP_TRANSLATOR_SCREENSHOT_PATH
```

Чтобы отдельно увидеть карточку с раскрытым ответом, задайте `POOP_TRANSLATOR_REVIEW_SCREENSHOT_PATH` и повторите `npm run smoke:browser`; используйте путь вне репозитория для тестового снимка.

Снимок PDF-вкладки задаётся через `POOP_TRANSLATOR_PDF_SCREENSHOT_PATH`. Browser smoke загружает сгенерированные fixture-файлы из `tests/fixtures/`: один содержит две текстовые страницы, второй — растровую страницу для настоящего OCR fallback.

`smoke:real` не устанавливает `SmokeTranslator`. Стабильные Google Chrome и Edge больше не принимают флаги боковой загрузки расширений, поэтому автоматический сценарий использует поставляемый Playwright Chromium: [документация Playwright](https://playwright.dev/docs/chrome-extensions). На проверенной машине Chromium 153 увидел EN→RU и RU→EN как `downloadable`, но пакет не завершил загрузку за 190 секунд; сценарий корректно завершился ошибкой. Для быстрой диагностики можно задать `POOP_TRANSLATOR_REAL_TIMEOUT_MS`. Окончательную проверку установленного Google Chrome выполняйте вручную.

## Ручная приёмка в установленном Google Chrome

1. Загрузить `dist` через `chrome://extensions`, записать версию Chrome и ОС.
2. Подготовить EN → RU; перевести `The cat is sleeping on the chair.` и проверить смысл. Затем RU → EN: `Кошка спит на стуле.`. Не требовать единственной дословной формулировки.
3. Проверить FR/JA/KO/ZH и автоопределение. Если пара ещё не загружена, нажать «Подготовить и перевести»; отдельно проверить короткие слова и смешанный текст. Доступность пары и качество перевода фиксировать для установленной версии Chrome.
4. На обычной HTTPS-странице проверить выделение, перетаскивание карточки за кнопку и стрелками, рост после появления значений, верхний/нижний край и оба пункта настоящего контекстного меню.
5. Нажать «Выбрать область» и обвести крупный EN-текст на картинке; проверить редактирование и повторный перевод. Повторить с RU, JA, KO, упрощённым и традиционным ZH после выбора OCR-языка и через `Alt+Shift+P`.
6. Перевести `bank`, добавить отдельный вариант в словарь, изменить заметку, проверить отсутствие дубля при повторном добавлении пары.
7. Выключить историю и проверить, что новые записи не добавляются; включить обратно.
8. Запустить перевод страницы, нажать «Начать», закрыть popup и дождаться изменения текста. Вернуть оригинал. Проверить отмену и повторный запуск.
9. Проверить, что формы и код не затронуты; изменение текстового узла самим сайтом не должно затираться при восстановлении.
10. Открыть «Карточки», вспомнить сохранённую пару, раскрыть ответ, оценить её и проверить срок. После перезапуска Chrome убедиться, что прогресс, словарь, история и настройки сохранились.
11. Открыть PDF-вкладку из popup. Проверить текстовый PDF и скан, авто/явный выбор источника, несколько целей, отмену, предупреждения после 20 МиБ/50 страниц, файл на 51 странице, жёсткие пределы 100 МиБ/200 страниц и единый TXT.
12. Экспортировать JSON v4 и импортировать его без дублей. При наличии старых копий v1–v3 проверить их импорт отдельно.
13. После подготовки повторить перевод, PDF и OCR без сети. Записать результат отдельно от автоматического smoke.

Не сохранять личный текст и профиль браузера в тестовые артефакты репозитория.

## Проверка конкретной картинки

Для локального PNG можно заменить цветной тестовый рисунок и перечислить ожидаемые фразы через `|`:

```powershell
$env:POOP_OCR_FIXTURE_PATH = 'D:\Temp\ocr-example.png'
$env:POOP_OCR_EXPECTED_TEXT = 'first phrase|second phrase'
npm run smoke:ocr
Remove-Item Env:POOP_OCR_FIXTURE_PATH
Remove-Item Env:POOP_OCR_EXPECTED_TEXT
```

Файл читается локальным тестовым сервером и не копируется в репозиторий. Без `POOP_OCR_EXPECTED_TEXT` скрипт только выводит результат пользовательской картинки; встроенная проверка EN/RU/DE/JA/KO/ZH остаётся обязательной.

Дополнительный проход OCR использует увеличение и преобразование светлых букв в тёмные на белом фоне, согласно [рекомендациям Tesseract по качеству входного изображения](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html). Оценка confidence используется как эвристика выбора результата, а не как процент правильно распознанных символов.
