# Poop Translator Design

Сверено с кодом версии 1.2.0 на 2026-09-14. Это описание реализации; история аудита и оставшиеся предложения перечислены в [аудите](../../audit-2026-09-13.md).

## Цель

Создать бесплатное персональное расширение Chrome «poop translator» для перевода между английским и русским: вручную, из выделения, контекстного меню и для основного содержимого страницы. История, словарь и настройки хранятся только в `chrome.storage.local`.

## Техническое решение

Расширение использует Manifest V3, TypeScript и Vite без UI-фреймворка. Встроенный Chrome Translator API является единственным обязательным движком: он не требует ключа и после загрузки языкового пакета работает локально. Перевод запускается в документном контексте popup или content script, где доступен Web API; service worker создаёт контекстное меню и маршрутизирует команды.

Для исходного языка доступны `en`, `ru` и `auto`. Автодетект различает чисто латинский и кириллический текст локально, а для смешанного текста использует Language Detector API. Автоматическая подготовка запускает обе пары EN ↔ RU внутри пользовательского клика и показывает прогресс.

Несколько значений отдельных слов и коротких фраз берутся из встроенных словарей FreeDict EN→RU и RU→EN. Данные разбиты по направлению и первой букве, поэтому загружается только нужный фрагмент. Запросы к внешним словарным сервисам не выполняются.

## Компоненты

- `background.ts`: установка контекстного меню, доставка команд активной вкладке и единая последовательная очередь всех изменений `chrome.storage.local`.
- `content.ts`: кнопка у выделения, Shadow DOM карточка результата, перевод страницы, восстановление оригинала.
- `popup/`: ручной перевод, история, словарь, настройки, запуск перевода страницы.
- `core/translator.ts`: адаптер Chrome Translator/LanguageDetector с проверкой доступности, прогрессом и понятными ошибками.
- `core/dictionary.ts`: локальный поиск нескольких значений и фильтрация повторов.
- `core/storage.ts`: версия схемы, нормализация, история, словарь, настройки и последовательная запись.
- `core/page-translation.ts`: выбор текстовых узлов, пакетирование и безопасное восстановление.
- `shared/`: типы, протокол сообщений и идентификаторы запросов.

## Потоки данных

Ручной перевод выполняется в popup, после успеха popup добавляет запись в историю. Кнопка выделения выполняет перевод в content script. Popup и content script отправляют все изменения данных в service worker, поэтому одновременные записи разных вкладок проходят через одну очередь и не перезаписывают друг друга. Пункт контекстного меню посылает content script команду с выделенным текстом. Перевод страницы запускается из popup сообщением, выполняется в content script пакетами и не сохраняется в историю.

## Перевод страницы

Content script выбирает `main`, `article`, `[role=main]` или `body`, собирает видимые текстовые узлы и пропускает `script`, `style`, `code`, `pre`, формы, `contenteditable` и элементы расширения. Исходное значение и последнее значение расширения хранятся в `Map<Text, Snapshot>`. При восстановлении узел меняется только если его текущее значение совпадает с последним переводом расширения. Операция поддерживает отмену и прогресс.

## Данные

Схема `v1` содержит `settings`, `history` и `dictionary`. Настройки включают направление, историю, кнопку выделения и масштаб текста 100/115/130% с крупным значением 115% по умолчанию. История ограничивается 500 последними записями. Дубликаты истории по `requestId`, а словаря по нормализованной паре `original + translation` не создаются. При выключенной истории новые переводы не записываются. Версионированная JSON-копия экспортирует состояние; импорт применяет настройки и объединяет уникальные записи через очередь service worker.

## Интерфейс

Popup шириной 404 px имеет четыре вкладки: «Перевод», «История», «Словарь», «Настройки». Визуальный образ — карманная игрушка-переводчик: тёмные сливово-графитовые поверхности, насыщенный розовый и сиреневый акценты, мягкие скругления, масштабируемый текст, крупные состояния фокуса и маленький poop-персонаж. Варианты перевода выводятся кнопками и добавляются в личный словарь одним нажатием. Карточка выделения измеряется после каждого изменения содержимого, открывается вверх при нехватке места снизу и всегда ограничивается viewport. Анимации отключаются через `prefers-reduced-motion`.

## Ошибки и ограничения

На системных страницах Chrome content script недоступен; popup сообщает об этом. API и языковая пара проверяются во время выполнения. Первая загрузка модели может занять время. Динамически добавленный текст страницы переводится при повторном запуске. PDF, canvas, изображения и закрытый Shadow DOM не переводятся.

## Проверка

Vitest покрывает нормализацию данных, историю, локальные словарные варианты, оба направления через заглушки API, разбиение текста и безопасное восстановление DOM. `npm run typecheck` проверяет типы отдельно от сборки Vite. `npm run smoke` проверяет manifest, обязательные файлы и два словарных фрагмента.

`npm run smoke:browser` загружает `dist` в Chromium с временным профилем. В popup Translator и LanguageDetector заменены заглушками. Проверяются вкладки, направления, оба словаря, сохранение варианта, backup, масштаб, content script, скрытие статуса и приглашение перевода страницы. Сценарий не нажимает «Начать» и не проверяет реальное преобразование страницы. `npm run smoke:real` не ставит заглушки и проверяет настоящий API, если Chromium смог скачать языковой пакет. Ручная проверка описана в [testing.md](../../testing.md).
