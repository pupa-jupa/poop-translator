Основные возможности реализованы, архитектура небольшая и понятная: TypeScript без UI-фреймворка, документные контексты для Chrome AI, единая очередь записи в background, локальные словарные фрагменты и восстановление DOM с проверкой текущего текста. ## Инженерные пробелы по приоритету

### P1 — доказательство реального перевода

`scripts/browser-smoke.mjs` всегда устанавливает `SmokeTranslator` и `SmokeLanguageDetector` в popup. Ветка `POOP_TRANSLATION_SMOKE=1` вызывает ту же заглушку, но печатает `Real translation`. Это ложноположительная проверка настоящего API. Проверка страницы посылает две команды, проверяет один prompt и закрывает его через RESTORE_PAGE, не нажимая «Начать».

Нужны два явно разных сценария: детерминированный UI/RPC smoke и проверка настоящего Chrome API без подмены. Второй должен фиксировать версию Chrome, доступность пары, реальный перевод EN/RU, выделение, native ПКМ и страницу после закрытия popup. Отсутствие модели должно быть отдельным пропуском/ошибкой, а не зелёным результатом заглушки.

### P1 — ошибки записи и резервная копия

`src/core/storage.ts` сохраняет весь объект под одним ключом; история ограничена количеством 500, словарь по размеру не ограничен. Обработка quota и экспорт отсутствуют. `popup.ts` выполняет запись истории в том же try, что и успешный перевод: отказ storage превращается в сообщение об ошибке перевода. Некоторые действия используют promise без catch (например сохранение результата и копирование), поэтому отказ не получает понятного UI.

Предлагается: отдельное сообщение «Перевод готов, историю сохранить не удалось», обработка отказов каждой пользовательской команды, индикатор занятого места и локальный экспорт/импорт JSON с версией схемы, проверкой размеров и дедупликацией. Chrome документирует лимит storage.local 10 MB и удаление данных при удалении расширения: [Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage).

### P2 — поддерживаемая среда и CI

В CI закреплён Node 20, несмотря на Node 24 у локальной среды. На дату проверки Node 20 имеет статус EOL, Node 24 — LTS: [официальные версии](https://nodejs.org/en/about/previous-releases). Перевести CI на Node 24, согласовать `engines` и файл версии среды; выполнить `npm ci` и весь набор проверок на выбранной версии.

Дополнить CI браузерным smoke, проверкой всех словарных фрагментов и расхождений пересобранного dist. Сейчас файловый smoke читает только два примера словаря. Закрепление actions полными SHA и автоматические обновления зависимостей — следующий шаг воспроизводимости, не доказательство найденной уязвимости.

### P2 — слова, значения и направления

`LocalDictionary` ищет точное совпадение, без лемматизации. `selectAlternativeVariants` показывает максимум восемь вариантов. Генератор уплощает TEI и назначает первую часть речи всей записи. Примеры употребления, контекстные пометы и ранжирование по предложению отсутствуют; UI не объясняет пустой результат поиска.

Авто-режим распознаёт алфавит, затем при необходимости использует detector с порогом 0.65 и fallback en. Это переключатель двух языков, не универсальное распознавание. При переводе страницы режим применяется к каждому фрагменту; смешанная страница может переводиться в обе стороны. Нужен отдельный явный целевой язык страницы.

### P2 — размер текста и доступность

Поле ввода 17 px, результат 18 px, но многие подписи, вкладки и вторичные действия в `src/popup/popup.css` остаются 11 px. README теперь описывает это точно. Предлагается пользовательский масштаб 100/115/130%, проверка переполнения, фокуса, контраста и клавиатурных сценариев. Текущие DOM-тесты имён элементов не доказывают полную доступность.

### P2 — проверка входных данных

`isStorageMutationMessage` проверяет оболочку и имя операции, но не payload; background использует `as` для приведения типов. `normalizeState` нормализует v1, а не выполняет полноценную миграцию будущих схем. Добавить отдельные валидаторы payload с конечными timestamp и лимитами строк, тесты испорченного состояния и отказов записи. Это рекомендация устойчивости, а не утверждение об эксплуатации со страницы.

### P3 — выпуск и сопровождение

Нужны готовый ZIP расширения в GitHub Releases, changelog, объяснение обновления распакованной версии без удаления данных, описание приватности/разрешений и неизменяемые источники словаря с контрольными суммами. Сейчас TEI URL обновляемые: совпадение версии и точную воспроизводимость нельзя вывести из самого адреса.

## AGENTS.md на сентябрь 2026

Единого стандарта «лучших практик сентября» нет. Использованы действующие официальные правила обнаружения и практические требования этого кода. В корневом AGENTS.md должны быть реальные команды, карта контекстов, инварианты и ограничения тестов. Длинные планы, история работы и универсальные требования ко всем задачам туда не включены.

OpenAI описывает загрузку инструкций от корня к текущему каталогу, приоритет `AGENTS.override.md` и стандартный общий лимит 32 KiB. Для review рекомендует краткие правила конкретного поведения: [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Добавленный файл значительно меньше этого лимита; отдельные вложенные инструкции для такого размера проекта пока не нужны.

Рекомендации Chrome согласуются с текущим размещением Translator в документных контекстах и запуском создания модели из клика: [Translator API](https://developer.chrome.com/docs/ai/translator-api). Для автоматизации расширений Playwright документирует persistent Chromium context: [Chrome extensions](https://playwright.dev/docs/chrome-extensions).

## Состояние предложений после версии 1.2.0

1. **Экспорт и импорт словаря/истории — реализовано.** JSON имеет версию формата, импорт объединяет уникальные записи через background-очередь.
2. **Настройка масштаба текста — реализовано.** Доступны 100%, 115% и 130%; значение 115% используется по умолчанию.
3. **Диагностика первого запуска — частично.** Состояния API и ошибки показываются, а реальный smoke отделён от заглушки. Можно дополнительно показывать размер и состояние загрузки языкового пакета, если Chrome откроет эти данные приложению.
4. **Примеры употребления и части речи по отдельным значениям — не реализовано.** Для этого нужен подходящий локальный источник с совместимой лицензией.
5. **Явный язык результата для страницы — не реализовано.** Это остаётся полезным для смешанных EN/RU страниц.
6. **Озвучка, карточки повторения и теги — не реализовано.** Их стоит добавлять после ручной приёмки версии 1.2.0 в установленном Google Chrome.

Следующий практический приоритет: ручная проверка настоящей модели и native-контекстного меню → явный язык результата страницы → контекстные примеры → карточки повторения. Не расширять число языков до стабилизации EN/RU.
